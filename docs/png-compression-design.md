# PNG 一键压缩实施方案

## 目标与边界

- 功能仅面向已索引、可访问的静态 PNG 图片。
- 用户可独立选择 pngquant（有损）或 OxiPNG（无损），也可同时选择。
- 同时选择时，处理顺序固定为 `pngquant → OxiPNG`。
- “不允许任何像素变化”模式强制只使用 OxiPNG。
- 压缩完成后，弹窗中的预览切换到结果图片；保存行为与一键抠图一致。
- 如果处理结果不小于原文件，结果缓存直接使用原 PNG，保证保存不会造成体积回退。

## 前端方案

### 入口限制

资源详情面板通过 `canCompressPng` 判断入口是否可见，条件为：

1. 资源类型为图片；
2. 资源已索引且未缺失；
3. 格式或文件名扩展名为 PNG（大小写不敏感）。

该判断只控制界面可见性，不能替代后端校验。

### 压缩弹窗

`PngCompressionDialog` 复用一键抠图的弹窗布局和保存交互，包含：

- 原图/结果预览舞台；
- pngquant 与 OxiPNG 技术开关；
- pngquant 1–100 有损强度；
- OxiPNG 1–6 优化级别；
- 像素严格不变模式；
- 压缩前后大小、节省比例和实际步骤；
- 另存为、原图目录、覆盖原图三种保存模式。

设置变化后，已有结果被标记为过期，必须重新压缩才能保存，避免参数与结果不一致。

### 预览生命周期

原图和结果通过本地 Blob URL 展示。重新处理或关闭弹窗时撤销旧 URL，并调用后端丢弃未保存任务，避免缓存和内存泄漏。

## 后端方案

### 双重 PNG 校验

`png_compression` 模块在处理前从 SQLite 查询资源，并验证：

- 资源类型、扩展名和可用状态；
- 磁盘路径仍存在且扩展名为 PNG；
- PNG 文件签名与 IHDR；
- 宽高、像素数及预估 RGBA 内存不超过应用安全上限。

### pngquant 管线

使用 pngquant 官方量化引擎 libimagequant：

1. 将 PNG 解码为 RGBA8；
2. 将用户强度映射为 libimagequant 的目标质量范围；
3. 执行调色板量化与抖动；
4. 编码为带透明调色板的索引 PNG。

### OxiPNG 管线

OxiPNG 直接在内存中优化 PNG 字节。像素安全设置包括：

- `optimize_alpha = false`，不改写全透明像素的 RGB；
- `scale_16 = false`，不把 16 位通道缩减为 8 位；
- 不剥离 PNG 元数据块；
- 限制最大解压内存和单次优化时长。

### 组合与任务缓存

处理在 Tauri 阻塞线程中运行，不阻塞前端，也不创建外部控制台窗口。结果写入应用数据目录下的临时任务缓存，任务包含资源 ID、原路径、结果路径和尺寸。任务在保存、主动丢弃或过期清理时删除。

### 保存与覆盖

- 另存为/原图目录：先复制到同目录临时文件，再原子重命名；目标已存在时拒绝覆盖。
- 覆盖原图：先生成临时文件并备份原 PNG，再原子替换；随后更新 SQLite 的大小、修改时间、尺寸、缩略图、元数据状态和内容哈希状态。
- 如果索引更新失败，删除新文件并恢复备份；成功后删除备份并广播资源索引变化事件。

## 验证清单

- 非 PNG 不显示入口，伪造请求被后端拒绝。
- 两种技术均未选择时不能处理。
- 像素严格不变模式只能提交 OxiPNG。
- 两种技术同时选择时顺序为 pngquant 后 OxiPNG。
- OxiPNG-only 前后解码 RGBA 完全一致。
- 输出为有效 PNG，宽高不变且文件不大于原文件。
- 重复压缩、取消、另存和覆盖均清理任务缓存。
- 覆盖后资源索引、缩略图和详情大小刷新。
- 前端生产构建、Rust 全目标检查、完整 Tauri 桌面构建均通过。

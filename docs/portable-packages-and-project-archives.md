# Caevir Windows 可携带资产包与项目归档包

本文描述 Caevir Windows P2 的 `.caepack` 与 `.caeproject` 格式、兼容策略、安全边界和真实导入/导出流程。两种格式都是 ZIP 容器，但不应当作任意 ZIP 解压；只能通过 Caevir 的受校验导入命令恢复。

## 格式概览

ZIP 根目录固定包含 UTF-8 `manifest.json`。清单使用 `schemaVersion: "1.0.0"`，并以 `packageType` 区分：

- `caevir.assetPackage`：一组资产库原件、有效缩略图和可迁移元数据。
- `caevir.projectArchive`：项目配置、逻辑目录、项目资产关系、项目副本和已收集的外部引用原件。

清单的 `createdAt` 是 Unix epoch 毫秒，`appVersion` 是导出应用版本。`entries` 列出除清单自身以外的每个 ZIP 条目，并保存相对 POSIX 路径、角色、未压缩大小和小写 64 位十六进制 BLAKE3。清单与 ZIP payload 必须一一对应：拒绝额外文件、遗漏文件、重复路径和同一文件被多个资产引用。

资产记录不传输 SQLite rowid、数据库主键或原机器绝对路径。它保存包内 ID、文件名、逻辑目录、媒体类型、扩展名、包内文件/缩略图路径、缺失状态及以下可迁移信息：

- 来源方式、来源 URL、作者和作者解析状态；
- 中文名、拼音、英文/中文 AI 提示词；
- 图片尺寸、时长和音频流信息；
- 响度信息；
- 与当前文件修改版本匹配的 dHash、调色板和特征版本；
- 标签名、标签组、排序、颜色、说明、归档状态和适用资源类型。

项目清单另外保存项目名、全部逻辑目录和成员关系。`reference` 成员在导出时会收集外部源文件；`copy` 成员归档当前项目副本。恢复时引用路径指向新项目内文件或已用 BLAKE3 复用的本机资产，不再依赖原机器路径。缺失成员仅保存不含绝对路径的显示快照，并以明确的缺失状态恢复。

## 兼容策略

版本按主版本判断：

- 当前实现接受 `1.x`，未知可选 JSON 字段由 Serde 忽略，便于同一主版本向前扩展。
- 未知更高主版本会在创建 staging 之前拒绝，并提示升级 Caevir。
- `0.x`、包类型不匹配、清单语义不一致会拒绝。

新增依赖只有固定版本 `zip = 2.4.2`，并关闭默认特性、仅启用 Deflate。标准库不提供 ZIP 容器读写，而该功能必须流式压缩/解压，所以此依赖不可由现有 `blake3`、`rusqlite` 或 Tauri 能力替代。版本固定是为了让格式行为和安全验证可复现。

## 安全边界与资源限制

导入会先完整预检 ZIP central directory 和 manifest，再创建 staging。限制为：

- 最多 100,000 个 payload 条目（另加一个 manifest）；
- manifest 最大 16 MiB；
- 单文件最大 8 GiB；
- 总解压大小最大 32 GiB；
- 大于 1 MiB 的条目压缩比不得超过 200:1；
- 导入前通过 Windows `GetDiskFreeSpaceExW` 检查声明大小，并预留 256 MiB；项目恢复因可能同时保留项目副本和收集源，按两倍 payload 估算。

路径只允许使用 `/` 的相对路径。以下内容会拒绝：绝对路径、盘符、UNC、反斜杠、空段、`.`、`..`、NUL/控制字符、ADS 冒号、Windows 非法字符、尾点/尾空格、`CON`/`PRN`/`AUX`/`NUL`/`COM1-9`/`LPT1-9`，以及 Windows 大小写等价碰撞。ZIP 只接受 Stored/Deflated 普通文件，拒绝加密条目、符号链接、设备、FIFO、源文件或目标目录中的 Windows 重解析点。

解压时不信任 central directory：每个读取块都会再次计算实际单文件大小、累计大小和 BLAKE3；目标文件使用 `create_new`，不会覆盖 staging 内已有文件。这同时防御 ZIP Slip、压缩炸弹、条目篡改和大小写覆盖。

## 原子导出、导入与取消

导出流程：

1. 从真实 SQLite 读取所选资产或项目关系；演示资源不能导出。
2. 拒绝符号链接/重解析点，流式计算每个源文件 BLAKE3。
3. 在最终包的同目录写临时 ZIP；写入时再次计算哈希，源文件中途改变会失败。
4. `sync_all` 后原子替换最终包；已有目标先改名为同目录备份，提交失败会恢复旧包。

导入流程：

1. 系统文件对话框选择包，并选择实际资产落地目录或项目恢复父目录。
2. 预检格式、安全限制和磁盘空间；实际哈希本机同大小候选以判断完全重复。
3. 在最终目标同一父目录创建带操作所有权 marker 的 staging，流式解压和校验。
4. 校验完成后将 staging 原子改名为最终目录。
5. 使用单个 SQLite 事务映射本机 UID、合并标签/元数据并重建项目关系。
6. 数据库提交失败或用户取消时回滚事务，并且只删除所有权 marker 与当前操作匹配的 staging/final，避免并发竞争误删其他目录。

前端进度对话框展示当前阶段、条目和完成比例。运行中“取消”通过 Tauri 命令设置操作取消标记；Rust 在资产/成员、ZIP 条目、解压数据块和事务提交边界检查取消状态。完成页固定汇总成功、复用、跳过、冲突、失败和缺失，并可展开确定性改名或标签组冲突提示。

## 重复与冲突策略

- 完全相同：以实际文件 BLAKE3 和大小为准，复用已存在的 `available/library` 资产 UID，不复制第二份；已有非空元数据优先，只补空字段，标签取并集。
- 同名异内容：绝不覆盖。本机已有同名但没有相同内容时使用 `name (imported 2).ext`；包内或项目内大小写等价重名使用稳定递增后缀，并写入冲突汇总。
- 标签重名：当前数据库中标签名全局唯一。若包内同名标签属于不同标签组，保留本机标签并计入冲突，不静默迁组。
- 项目重名：同时检查项目数据库和目标文件夹，使用 `Project (imported 2)` 的第一个可用名称并汇总。
- 缺失成员：不会伪造文件；恢复为 `source_missing` 关系并计入缺失汇总。

## 当前限制

- `.caepack` 导入需要用户选择原件落地目录；Caevir 不隐式把可携带原件放入缓存。
- 缩略图随包验证并恢复到目标内 `.caevir/` 缓存目录。若平台资产协议无法直接显示该任意用户目录，后台预览任务会按原件重新生成应用缩略图。
- 项目归档以数据库登记的项目资产关系为完整边界；项目目录中与 Caevir 项目无关、未登记的普通文件不会作为资产关系导入。
- 本实现对进程内失败与取消执行完整回滚。操作所有权 marker 可防止错误清理并发目录；Windows 在原子目录改名之后、SQLite 提交之前若发生进程级强制终止，可能留下一个未登记但内容完整的恢复目录，重新导入会通过确定性重命名避开它。
